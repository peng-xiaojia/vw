# 外部软件与终端入口验收

日期：2026-10-15。基线提交 `f72dfaa`。

## 行为

展示/源码旁与文件菜单提供两个入口，未打开文件或当前文档繁忙时灰色。其他软件打开使用 Windows SHOpenWithDialog，独立 STA 与主窗口 HWND；不自动调用默认关联，因此不会因为 vw 为默认程序而直接循环打开自己。程序不主动更改默认关联。

终端使用系统目录下的 Windows PowerShell，固定 `-NoLogo -NoProfile -NoExit` 参数，文件父目录通过进程工作目录传入；目录标签直接用本目录。中文、空格、`&`、`$`、`;` 等字符不进入命令文本，也不执行 SH/BAT/PowerShell 文件本身。终端为用户请求的新交互控制台。

两个动作都先检查未保存草稿。取消/保存失败不启动；不保存仍保留本软件草稿，外部软件打开磁盘版本。操作绑定发起请求的标签，切换标签不会变更路径；关闭等待应用选择器完成后才释放文档。归档成员前后端均拒绝交出临时物化文件，提示先导出。

外部编辑不会自动刷新当前预览；关闭该标签后重开可读取最新内容。原有保存冲突检测保持有效。

- 独立 identifier `dev.vw.test.editor` 原生 WebView2 回归：按钮初始禁用、文件打开后启用、实际 `vw_open_elsewhere` IPC 拒绝无效句柄；原编辑/格式化/编码/Office 回归通过。
- 两名只读代码审查代理分别检查前端状态与后端 Windows 启动逻辑，未发现高、中优先级问题。

窄窗口截图曾复现目录浮层覆盖新按钮，定位为目录绝对定位相对于整个文档区。改为相对于正文定位后，覆盖按钮的点击命中测试由失败变为通过。截图：`target/ui-external-tools-narrow.png`。

应用选择器的真实选择和终端交互未进行人工桌面验收。自动测试不启动用户的其他编辑器或执行脚本，也不打扰正在运行的主应用。
